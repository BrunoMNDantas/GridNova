# GridNova decisions

Only items under **Approved** are commitments. Items under **Proposed** are open.

## Approved

### 1. Language: TypeScript (strict)

The typed API (generic row types, inferred column values) is central to the library's value.

### 2. Package manager: pnpm

Strict dependency resolution catches undeclared dependencies on the developer's machine, before they reach consumers. Publishing to npm and consumer installs are unaffected.

### 3. Public API: `<Grid>` with slots and CSS variables

- Users get a styled `<Grid>`, customizable through slots (replacing parts such as `Cell` or `Header`) and CSS variables.
- Internals are layered: logic lives in hooks that render nothing, components stay thin, CSS does styling.
- The hooks are **not** public API for now. They may be exported later if proven stable and needed.
- Slots are added per feature as needed, not speculatively. Each slot's props are public API.

### 4. State convention: controlled and uncontrolled

Any state a user could reasonably want to own follows one pattern: `value` (controlled), `defaultValue` (initial, uncontrolled) and `onValueChange`. Example: `filter`, `defaultFilter`, `onFilterChange`.

- Uncontrolled by default. If the controlled prop is passed, the grid uses it.
- Each state is exposed per feature, when the feature is built. Each exposed state's shape is public API.
- Switching between controlled and uncontrolled mid-life is unsupported; warn in development.
- Both modes are tested for every exposed state.

### 5. Repository layout (direction)

- Library at the repo root, published as a single npm package.
- `playground/`: a development-only Vite app that consumes the library. Not published.
- `docs/` for decisions, feature documents and the learning checklist.
- Folders under `src/` (`components`, `hooks`, `types`, `styles`) are a starting guess. A folder is created only when its first real file needs it.
- No monorepo split until a concrete need appears.

### 6. Build tooling: Vite

Vite for the playground and Vite library mode for the library build. Type declarations (`.d.ts`) are generated by `tsc --emitDeclarationOnly` as an extra build step and wired through the `types` and `exports` fields of `package.json`. If the library build proves awkward, tsdown is the fallback and the playground is unaffected.

### 7. React compatibility

`react` and `react-dom` are peer dependencies with range `^18 || ^19`, never bundled. Development targets React 19 first; both versions are tested once CI exists.

### 8. Testing: Vitest and React Testing Library

Tests assert user-visible behavior. Test files sit next to the code (`Grid.test.tsx`). Browser tests (Playwright) are deferred until a feature depends on real layout, such as virtualization.

### 9. Lint and format: ESLint (typescript-eslint) and Prettier

Includes the `react-hooks` and `jsx-a11y` rule sets.

### 10. TypeScript configuration

`strict`, `noUncheckedIndexedAccess` and `moduleResolution: "bundler"`.

### 11. CI: minimal GitHub Actions workflow now

On push and pull request: install, lint, type-check, test, build. Node pinned to the current LTS, pnpm with caching (exact versions verified at scaffold time). The React 18/19 test matrix is added together with the first real tests.

### 12. Deferred until there is something to act on

- **Sonar / coverage reporting:** after the first features exist (SonarCloud is free for public repos; Codecov is a lighter alternative).
- **Demo site:** deploy the playground to GitHub Pages once the grid renders something worth showing, then link it from the README.
- **Release process:** versioning, changelog and npm publishing (Changesets to be considered then). Until then `package.json` stays `private: true`.

### 13. Scaffold applied (2026-11-17)

Scaffold approved in plan mode and created. Implementation details that came out of it:

- Corepack provides pnpm; the version is pinned in `packageManager` (pnpm 12.21.0). Node 24 (`.nvmrc`).
- `pnpm-workspace.yaml` sets `minimumReleaseAge` to 14 days, so pnpm refuses package versions newer than two weeks.
- **TypeScript is pinned to 6.0.x and ESLint to 9.x**: typescript-eslint 8.72 supports TypeScript below 6.1, and eslint-plugin-jsx-a11y 6.10 supports ESLint up to 9. Revisit when those plugins publish support for TypeScript 7 and ESLint 10. pnpm flags ESLint 9.39 as deprecated; that is accepted until then.
- `src/components/Grid.tsx` is a scaffold placeholder (plain generic table) used only to prove the toolchain; the first real feature replaces it.

## Proposed (not yet approved)

- **Output format: ESM only for now.** The plan said ESM + CJS, but the `.d.ts` produced by `tsc` under `"type": "module"` describes ESM only; shipping a CJS build with those types would give CommonJS consumers wrong types. Adding CJS properly needs separate `.d.cts` output and a package check (e.g. publint or arethetypeswrong). Decide before the first release.
